# Phase 3 — Database Schema Design

## 3.1 Database Purpose

The database will store business sales and transaction data required by the Conversational Analytics Platform.

The stored data must support the 17 approved use cases defined in Phase 2, including sales analysis, profit analysis, category and regional analysis, time-based trends, customer order lookup, and sales-profit relationship analysis.

The database schema is designed for Google Firestore. The initial design uses a single flat collection and does not require separate customer, product, or inventory collections.

---

## 3.2 Schema Design Principles

The schema follows these principles:

* One Firestore collection will store the business transaction data.
* One document will represent one order or transaction record.
* The design will use a flat structure to keep data retrieval simple for the initial project scope.
* Fields are based on the approved Phase 2 requirements.
* No additional fields are included in the initial schema.
* Field names use consistent `snake_case` naming.
* The schema must support filtering, grouping, sorting, ranking, aggregation, time-based analysis, record lookup, and numerical relationship analysis.

---

## 3.3 Field Definitions

The initial schema contains the following 12 fields.

| Field Name      | Firestore Type | Required | Description                                         | Example             |
| --------------- | -------------- | -------- | --------------------------------------------------- | ------------------- |
| `order_id`      | String         | Yes      | Unique identifier for an order or transaction.      | `"CA-2024-1001"`    |
| `order_date`    | Timestamp      | Yes      | Date and time when the order was recorded.          | Firestore Timestamp |
| `product`       | String         | Yes      | Name of the product associated with the order.      | `"Office Chair"`    |
| `category`      | String         | Yes      | Business category of the product.                   | `"Furniture"`       |
| `city`          | String         | Yes      | City associated with the sales record.              | `"New York"`        |
| `region`        | String         | Yes      | Geographic region associated with the sales record. | `"East"`            |
| `sales`         | Number         | Yes      | Total sales amount for the record.                  | `1250.50`           |
| `quantity`      | Number         | Yes      | Number of units sold.                               | `5`                 |
| `unit_price`    | Number         | Yes      | Price of one unit of the product.                   | `250.10`            |
| `discount`      | Number         | Yes      | Discount applied to the order or transaction.       | `0.10`              |
| `profit`        | Number         | Yes      | Profit generated by the record.                     | `180.25`            |
| `customer_name` | String         | Yes      | Name of the customer associated with the order.     | `"John Smith"`      |

---

## 3.4 Field-Level Validation Rules

Each record must follow the following basic validation rules:

| Field           | Validation Rule                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------- |
| `order_id`      | Required and must not be empty.                                                                                     |
| `order_date`    | Required and must be stored as a valid Firestore `Timestamp`.                                                       |
| `product`       | Required and must not be empty.                                                                                     |
| `category`      | Required and must not be empty.                                                                                     |
| `city`          | Required and must not be empty.                                                                                     |
| `region`        | Required and must not be empty.                                                                                     |
| `sales`         | Required and must be a valid numeric value.                                                                         |
| `quantity`      | Required and must be a valid numeric value greater than zero.                                                       |
| `unit_price`    | Required and must be a valid numeric value greater than or equal to zero.                                           |
| `discount`      | Required and must be a valid numeric value.                                                                         |
| `profit`        | Required and must be a valid numeric value. Negative values are allowed because a transaction may result in a loss. |
| `customer_name` | Required and must not be empty.                                                                                     |

## 3.6 Query Requirements

The database must support the approved Phase 2 use cases through filtering, grouping, sorting, aggregation, and date-based queries.

| Requirement           | Example                        |
| --------------------- | ------------------------------ |
| Aggregation           | Total sales, total profit      |
| Filtering             | Sales for a specific city      |
| Grouping              | Sales by category or region    |
| Sorting               | Products by sales              |
| Ranking               | Top 5 products by sales        |
| Date filtering        | Sales within a date range      |
| Time grouping         | Monthly sales                  |
| Customer lookup       | Orders for a specific customer |
| Relationship analysis | Sales vs profit                |

The AI engine will identify the required fields and operations from the user's question. The backend will then use this structured information to retrieve and process the actual data stored in Firestore.

## 3.8 Final Schema

The final Firestore schema contains 12 fields:

`order_id`, `order_date`, `product`, `category`, `city`, `region`, `sales`, `quantity`, `unit_price`, `discount`, `profit`, `customer_name`

The data will be stored in a single `sales` collection, with one document representing one transaction record.

### Example Document

```json
{
  "order_id": "CA-2024-1001",
  "order_date": "Firestore Timestamp",
  "product": "Office Chair",
  "category": "Furniture",
  "city": "New York",
  "region": "East",
  "sales": 1250.50,
  "quantity": 5,
  "unit_price": 250.10,
  "discount": 0.10,
  "profit": 180.25,
  "customer_name": "John Smith"
}
```

The `order_date` value will be stored as a Firestore `Timestamp` in the actual database.
